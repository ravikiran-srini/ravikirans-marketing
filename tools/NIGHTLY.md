# Morning job

Runs every day at about 8 AM IST. Prepares today's LinkedIn post (published by Make at 7 PM IST). Nothing here is fixed: it follows the current lists, so new categories, courses, books and videos are picked up automatically.

## Steps
1. **Refresh lists.** Add anything new, never remove or reorder existing rows.
   - `categories.csv`: from `https://ravikirans.com/wp-json/wp/v2/categories?per_page=100`. A new category with at least 3 posts gets `include` = yes if it is a vendor or certification, otherwise no.
   - `items.csv`: courses from `https://ravikirans.com/ravikiran-srinivasulu-udemy-courses/`, books from `https://leanpub.com/u/ravikirans`, videos from the Make data store 262859, key `ytfeed` (the channel's latest uploads as RSS, refreshed daily; read it with the Make tool `data-store-records_list`). If a source cannot be read, skip it.
   - For every new item, check that its exam is still current (vendor exam list or web search). If the exam is retired or replaced, add the row with `skip` = yes. Never delete rows.
2. **Choose today's item** (IST). Posting days: Mon, Tue, Thu, Sat; other days stop. If `plan.csv` has a row for today, use it. Otherwise choose the type:
   - `youtube`, `course` and `book` are eligible only if they have an item with `skip` empty and no post of that type in the last 7 days. Never two non-category posts in a row.
   - Among eligible types take the one posted longest ago (never posted first). If none is eligible, use `category`.
   - Within a type take the item posted least recently (never posted first; ties: more posts first for categories). `plan.csv` is the history of what was posted.
   - When every included category and every item with `skip` empty has been posted at least once, use type `post` instead: one blog post (list from `https://ravikirans.com/wp-json/wp/v2/posts?per_page=100&page=N`) on a current exam, not yet in `plan.csv`. Rank by traffic: Make data store 262859, key `traffic` (the sheet tab Traffic, first 6 columns, refreshed daily; columns separated by ` ## `, values by ` | `, first value of each column is its header, row order is the same in every column). Take the page URL column and the clicks (else impressions) column and choose the highest not yet posted. If `traffic` is missing or empty, take the most widely taken certification instead. Check the exam is current. If no such post is left, repeat the item posted longest ago.
   - Add the row to `plan.csv`: `date,type,title,url,pdf_url,status` with `status` = `planned`.
3. **Research.** Find what a candidate for this item most needs and most searches for, then build the content from checked facts only.
   - Read the page at the row's `url` (for `youtube`, the title and description from the feed). Then web-search what learners ask about this exam or topic (forums, Q&A sites, the vendor's exam guide) and read the vendor's official objectives and documentation.
   - Check every command, number, price and exam fact against an official source or the site's own pages. Drop anything you cannot confirm. Never invent exam codes, prices, percentages or claims. For a category, cover only current exams.
   - Decide the pages from that research. Nothing is fixed: a topic may need commands, a comparison, a decision path, how names or syntax are built (for example why PowerShell verbs work as they do: New creates, Add attaches to something that exists), tips for the technology, exam-day tactics, common mistakes, or a last-minute revision list. Use only what applies to this item.
4. **Carousel** (not for `youtube`): write a spec JSON (format in the `tools/render.py` header; `tools/example_red_hat.json` shows the layout only, never reuse its facts). The PDF has 10 pages: a cover, 8 content pages and the automatic last page.
   - Page 1 `cover`: one hook (surprising fact or common mistake), at most 12 words, key word in `*stars*`.
   - Content pages: type `page`, built from blocks (text, rows, bullets, code, note, table). Each page teaches one thing completely: how and why it works, an example, then a tip or warning. Explain the logic behind a command or term where that makes it easier to learn. Build up from basics to the end, and make the last content page a revision list.
   - Substance: a learner should be able to study each page for a minute or more, without it becoming an encyclopedia. Blank space at the bottom means add substance; text that shrinks or a "TOO DENSE" warning means trim. Plain language, headings at most 8 words, no emojis. Code lines at most 46 characters (continue with `\`).
   - Types `stat`, `cards`, `steps` and `code` stay available where they fit better.
   - `cta`: the row's `url` without `https://`. `label`: the category, course, book or post name. Set `cta_label` (small top label) and `cta_title` (heading) by type: category: "Free study guides" / "Free study guides for every <vendor> exam."; post: "Study guide" / "Read the full <exam> study guide."; course and book: say what the item actually is, taken from its page (for example "Practice tests" for a practice-test course, "Practice test book" for a practice-test book, "Video course" or "Beginner guide" otherwise) with a heading such as "Get <title> on Udemy." or "Get <title> on Leanpub."; never say practice tests unless the item is one. For a course or book also show what the learner gets and the real link.
   - Render: `python3 tools/render.py spec.json carousels/<date>-<slug>.pdf --png-dir /tmp/png`. Look at every PNG, fix overflow, overlap or empty space, render again.
   - The renderer outputs image pages with clickable links (button and social icons live in `tools/render.py`); keep text on red white and code lines unwrapped.
   - Save slide 1 as `carousels/<date>-<slug>-cover.png`.
5. **Write `today.json`** in the repo root, with keys `date, type, title, url, pdf_url, image_url, post, comment, facebook, x, page_text`.
   - Link `pdf_page` (not a key; category and post types only; the same slug as the `library.json` entry in step 6): `https://ravikirans.com/revision-library/<slug>/`. This is the page where readers give their email to get the PDF. Use it as the link in `facebook` and `x`, and as a second line in `comment`. Course, book and video days have none and keep the item's own link.
   - `pdf_url` / `image_url`: raw GitHub URLs of the PDF and cover PNG (`https://raw.githubusercontent.com/ravikiran-srini/ravikirans-marketing/main/...`). For `youtube`, `pdf_url` is empty and `image_url` is `https://img.youtube.com/vi/<id>/maxresdefault.jpg`.
   - `post` (LinkedIn): 130 to 200 words, short paragraphs. First line a specific, checked claim, under 100 characters. Then 2 lines on the exam or topic and who it helps. Then "Inside this 10-page guide:" and 4 to 6 short lines, each naming something concrete from the actual pages (not generic). One genuine question to the reader. Then "Study guides link in the comments." (course or book: "Link in the comments.", video: "Video link in the comments."). End with 2 hashtags. No URL, at most 2 emojis, no engagement bait. For a video there is no PDF: 60 to 90 words on what the video teaches.
   - `comment`: at most 40 words, one practical tip, then a blank line and the link with a short label ("Free study guides: ", "Practice tests: ", "Watch the full video: "). With a `pdf_page`, add a second line "Free PDF: " and that link.
   - `facebook`: 60 to 90 words, conversational, what the guide covers in 3 or 4 points, that the full 10-page guide is a free PDF (video: skip), then the link on its own line (`pdf_page` when there is one), then 3 hashtags.
   - `x`: under 220 characters including the URL: a hook line, the link (`pdf_page` when there is one), 3 hashtags.
   - `page_text`: one line and the URL, for the company Page share.
   - Write in first person as the site owner. Never use double quotes or backslashes in any text.
6. **Publish.** Set `pdf_url` and `status` = `ready` in `plan.csv`. For `post` and `category` types, also add the PDF to the website's Revision Library by appending an item to `items` in `library.json`: `{"slug":"<date>-<slug>","title":"<carousel title>","category":"<category name>","category_slug":"<slug from categories.csv>","date":"<date>","cover":"<image_url>","pdf":"<pdf_url>","summary":"<one plain sentence on what the PDF covers>","guide_url":"<url>"}`. Use the study guide's own category from `categories.csv`. Keep the file valid JSON. Commit PDF, cover PNG, `plan.csv`, `library.json` and `today.json` as Ravikiran with no Claude co-author or session lines. Run first: `git config user.name "Ravikiran Srinivasulu" && git config user.email "39718717+ravikiran-srini@users.noreply.github.com"`. Plain message such as `Add <date> <slug> post`. Push: `git -c push.negotiate=true push origin HEAD:main`.

## If something fails
- Render fails: still write `today.json` with empty `pdf_url` and `image_url` = `https://raw.githubusercontent.com/ravikiran-srini/ravikirans-marketing/main/brand/logo.png`, set `status` = `failed`. Make then posts the text with the logo.
- Page cannot be read: write nothing. Make emails the owner that the day was skipped.
